# 第一阶段实现与实验协议

日期：2026-10-13。范围：基于已记录反馈的离线可靠负采样和课程调度。当前实现不包含真实用户界面、在线探索策略、第二阶段残差传播或多兴趣模型。

## 1. 与历史基线的关系

原六个基线模块和 `code/main.py` 的运行行为保留。新增入口为 `code/experiment.py`，使用原 LightGCN/MF、训练图归一化、均值聚合、单负样本 BPR 及 Adam；训练仍每 batch 重新传播全图。

新实验仅在 validation 上定期评价；test 由独立命令在整个套件训练完成后评价。独立运行目录存配置、源代码 SHA256、数据 SHA256、环境、结构化指标、模型/优化器/随机数状态。

历史 Gowalla 数字不能作为 KuaiRand 的严格对照；新实验重新训练 A0。

## 2. 数据准备

入口：`python code/prepare_kuairand.py --raw-root ... --output ...`。不会覆盖已经存在的准备目录。

支持官方 KuaiRand 日志字段，使用标准库 CSV 与 SQLite 流式处理，避免一次加载全部原始日志。Pure、1K 和完整版本不得混用。

默认协议：

- 训练：`date <= 20220428`；
- 验证：`20220428 < date <= 20220503`；
- 测试：`date > 20220503`；
- 正向信号：`is_like=1` 或 `is_follow=1` 或 `long_view=1`；可以显式改用 click，但它在不同界面含义不同；
- 同一事件正向信号与 `is_hate=1` 冲突时，不用于正负标签，计入审计；
- 训练期同一用户—物品对，只要存在已认可正向信号，就不能进入负证据池；
- 明确负证据：没有训练正向交互且出现 `is_hate=1`；
- 弱证据：该训练用户—物品的所有保留观察均没有正向信号/点击/长观看/拒绝。任何点击会阻止仅依据较早未点击记录赋予弱负证据；点击未达到所选正向规则时仍属未知。弱证据不被称为明确不喜欢；
- 训练用户至少有两条唯一正向交互；用户词表由训练正向交互筛选，物品词表仅来自训练曝光；
- 未来未知用户/物品记录不进入评价，数量写入审计。训练零正度物品保留并单独统计；
- 默认验证与测试正向目标来自 `is_rand=1`。这是随机曝光日志上的目标定义，不自动构成完整无偏推荐评估；
- 已有训练正向交互不再作为未来新目标；测试还排除所有验证时期已知正向交互，包括不属于随机曝光目标的记录。

产物：`train.txt`、`val.txt`、`test.txt`、`val_known.txt`、`evidence.csv`、ID 映射和 `manifest.json`。图与负证据只由训练时期产生。未来可能变成正例的物品，不利用未来身份从训练负样本中提前排除。

提供两种可显式选择的协议参数：`--positive-rule engagement|click`、`--eval-source random|all`。切换后应使用新的准备目录，并固定后再比较所有方法。

去重修复：四元组 `(user_id, video_id, time_ms, tab)` 不再作为唯一事件键。按完整观察内容去重，同四元组但不同字段的记录保留并审计；protocol.deduplication 为 `full_observation_v2`。服务器更新步骤见[去重修复说明](kuairand_duplicate_fix.md)。

## 3. 四组采样机制

每轮默认抽取与唯一训练交互数相同的 triplets。先从有合法负例的活跃训练用户中均匀抽用户，再在该用户正交互内均匀抽正例。这不是按每条交互逐条遍历。

| 组别 | CLI sampler | 当前机制 |
|---|---|---|
| A0 | uniform | 均匀随机未交互物品 |
| A1 | hard | 固定候选池中选最高分；其余 triplets 保留随机负例 |
| A2 | reliable | 同类候选池中按评分与负证据组合选择；保留随机负例 |
| A3 | curriculum | 与 A2 相同，但定向比例从零逐渐升到目标值 |

默认 A1–A3 的候选数为 20，其中一半候选来自该用户的训练负证据池，其余来自全物品合法随机候选。无证据用户退化为随机候选。候选有放回抽取，可能重复；同一方法配置下候选规则相同。

**A1 因此是反馈候选池上的困难选择对照，不是文献中纯均匀候选的困难采样完整复现。** 若需要额外纯困难对照，用单独实验的 `--evidence-fraction 0`，并记录数据与候选条件的差异。

A2/A3 的候选选择准则为：

```text
adjusted_score = model_score / temperature + reliability_beta * log(confidence)
```

取 adjusted_score 最大的候选。默认明确负证据为 1，弱证据为 0.2，未知为 0.05。这些是启发式证据权重，不是已经校准的真实负例概率。`reliability_beta=0` 且相同候选/温度时退化到困难选择。

定向比例默认 0.8。A3 在 `curriculum_epochs=100` 内线性升到 0.8；第一个训练 epoch 定向比例为 0。该长度独立于总 epochs，方便恢复训练。当前按 epoch 调度，反馈数量驱动调度属于后续实验。

候选评分使用每轮开始的停止梯度图表示快照。A1–A3 均使用同样刷新周期；这不缓存训练梯度，BPR 仍逐 batch 重新计算传播。记录快照、采样时间及候选打分数量。

## 4. 评价与检查点

- 验证排名屏蔽训练正交互；测试排名屏蔽训练及验证时期已知正交互。
- Top-K 不大于该用户剩余合法候选数，否则报错，避免掺入被屏蔽物品。
- 报告总体、用户活跃度和物品正向度分组。物品组的指标在全局排名上使用分组真值计算，不等价于只在该组内排序。
- 当前不评价点击率、线上长期奖励，也不从缺失数据推断任意新展示的结果。
- `last.pt` 保存完整训练状态；`best_val.pt` 根据第一个 top-K 的验证 NDCG 保存，无 Early Stopping。
- 默认正式比较固定训练预算后的 `last.pt`。若选择 best_val，必须在查看 test 前统一确定。
- 恢复要求相同训练参数、数据和源代码；允许增加总 epochs 的单次运行恢复。套件恢复要求原套件配置不变。
- 检查点与套件均保存源码指纹；最终评价要求使用生成该检查点的同版代码，避免用修改过的模型实现解释旧权重。
- 保存并恢复 Adam、sampler RNG、Python/NumPy/Torch RNG。CPU 测试检查与连续训练一致；跨设备/软件版本或 CUDA 稀疏算子的位级一致性不作保证。

## 5. 输出与解读

每个运行目录包含 metadata、launches、metrics.jsonl、检查点与完成标记。suite 完成后冻结全组检查点选择及 SHA，再单独 test，汇总 CSV/JSON 中的均值、样本标准差和相同种子的配对差异。

单个 seed 的标准差为 null，不假装为零；三个 seed 的差异也不自动证明统计显著。

需要特别关注：负反馈数量与稀疏度、候选来源分布、明确负例占比、主指标、分组结果、采样成本。若证据权重只把模型推向容易负例，可能降低训练价值；实际实验决定是否继续。
