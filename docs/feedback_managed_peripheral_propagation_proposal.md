# 第二阶段方案：反馈管理的边缘缓存与辅助传播连接

日期：2026-10-12  
状态：宽泛讨论稿。已记录为第二阶段候选方案，具体算法、连接类型和参数尚未定稿，尚未实现或验证。  
关联：[总体路线](algorithm_research_roadmap.md) · [第一阶段方案](feedback_driven_negative_sampling_proposal.md) · [两阶段共同关键约束](stage12_critical_constraints.md)

## 1. 本次讨论的构想

用户提出借鉴第一阶段的用户缓存与反馈学习：为边缘内容维护缓存，通过“指针”与推荐图建立联系，使用强化学习相关策略管理，并设置上下限。

本提案将它具体化为待讨论的研究问题：在保留真实交互图的同时，能否通过反馈选择、调整和撤销辅助连接，为边缘节点补充有用信息，并避免其表示被已有热门邻域同化？

“指针”仍需明确：仅路由到推荐候选列表，还是让缓存信息真正参与表示计算。前者主要影响曝光，后者才直接改变传播。本文重点讨论后者，同时保留前者作为必要对照；不把该解释视为用户已经选定的唯一实现。

## 2. NTCF 的启发与本方案的区别

NTCF 保留双向二部图，把每个节点的局部传播解释为根树，根据本节点与邻居的度数差异分配传播深度。其重点是节点自适应传播，而非将全图换成一棵树，或直接为边缘节点增加曝光。

因此区分两个问题：

- 自适应深度/层融合：现有邻域传播多少、保留哪些信息？
- 缓存与辅助连接：邻域信息不足时补充什么，如何判断连接有效？

本方案将第二阶段扩展到动态邻域增强，仍保留自适应层融合路线。是否联合使用，应通过独立与组合对照决定。

NTCF 原文使用 NGCF 风格的变换、激活等组件；借鉴其深度规则不意味着可以无说明地改变本项目 LightGCN 的数学定义。完整复现 NTCF 与在 LightGCN 上试验节点门控是不同实验。

来源：[NTCF 原文第 2—3 节](https://arxiv.org/html/2608.10297v1)。

## 3. 待验证假设

- H1：边缘节点需要的辅助信息量不同，受证据约束的选择可能优于统一补边。
- H2：使用真实反馈管理连接，比只凭模型相似度保留连接更可靠。
- H3：独立信息通道及门控能够限制错误辅助关系的传播影响。
- H4：缓存、过期管理和可撤销连接能适应反馈变化，而不把早期错误长期固化。
- H5：辅助邻域选择与自适应层融合可能互补，但收益不必然成立。

缓存、图增强和强化学习已有先例；独创性要针对最终选择/更新机制检索，并通过对照确认。

## 4. 怎样定义“边缘”

先区分局部结构边缘、全局低度、低曝光和零交互节点。它们可能重合，但不是同一种状态。

结构指标依据截至当前时间已确认的交互图计算。辅助连接不能算作真实度数，从而制造“补边成功”的假象。需要记录度数、邻域度数差异、曝光次数与反馈量等不同统计。

第一版可先选择一类目标节点，优先讨论低度物品；低度用户另作分组。具体阈值或分位数待定。无邻居节点的指标应有明确退化规则。

完全无交互且无内容/属性信息的节点没有充分个性化依据；缓存只能保存未知状态，不能凭空提供偏好信息。此类节点需辅助信息或真实探索，单独评价。

## 5. 原图与辅助信息分开

### 5.1 真实交互通道

保存当前实验协议认可的正向交互。静态实验只使用训练交互；在线实验只使用当时已经到达并符合规则的反馈。保留数据来源、事件时间及版本。

### 5.2 辅助通道

候选关系包括用户—物品假设、物品—物品协同/内容关系等，附带来源、证据、权重和有效期。它们不是自动成立的真实正交互。

物品—物品连接会改变原二部图关系类型，应有独立聚合定义。用户—物品辅助连接也需与真实交互分开记录，避免隐含标签污染。

不得把明确拒绝作为 LightGCN 原邻接矩阵中的负权边。负反馈先进入采样证据与策略状态；若研究有符号图，需要另行定义算法和对照。

### 5.3 概念门控

候选表示融合可写为：

```text
节点表示 = (1 - g_v) × 原图表示 + g_v × 辅助信息表示
```

g_v 是待定义的节点门控。两路表示需有一致维度及明确尺度；限制 g_v 的范围，不假设较少交互必然需要较大门控。

分别定义真实图与辅助通道的归一化、方向及更新规则。若选择把边并入同一邻接矩阵，需要明确这会改变端点度数及相关原边的归一化权重，不能声称只影响新增边。

自适应层融合仍可用于原图通道。只做层融合而计算全部层，不自动节省稀疏图传播成本。

## 6. 缓存与连接生命周期

建议保存物品/节点 ID、锚点、关系类型、来源、模型版本、可信度、最近反馈时间、启用状态及过期时间。缓存项与原图节点通过 ID 引用，不复制成多个含义不明的实体。

候选状态：

```text
候选关系 → 待验证辅助关系 → 暂时启用
                         ↘ 暂缓 / 过期
暂时启用 → 反馈后保留、降权或撤销
```

正向反馈若满足交互规则，可另外生成真实用户—物品事件；物品—物品辅助关系不能因某次点击自动升级为真实用户—物品边。

明确拒绝降低该上下文中相关候选的探索倾向，并增加第一阶段的负例证据，不自动证明历史正交互错误。未点击不直接撤销所有连接。

新增正反馈后，相应用户—物品对要及时失去负采样资格；对过期采样缓存和在途 batch 的处理需在实现前定义。未知辅助关系不自动成为高可信正例或负例。

## 7. 学习策略与上下限

先讨论最小动作空间：选择一条候选连接，或对其启用、减弱、撤销。容量及大部分执行规则先固定，避免第一版同时学习采样、展示、补边、深度和容量。

策略上下文可包含节点结构、证据量、候选关系、近期反馈、预算和当前模型版本。奖励依据独立反馈或预先约定的评估信号；模型高分本身不能证明连接可靠。

仅管理即时候选展示可沿用 Bandit；若动作持续改变邻域并影响多轮奖励，需要明确状态转移、延迟奖励和信用分配，再决定完整强化学习算法。

| 约束 | 讨论目的 |
|---|---|
| 缓存容量与有效期 | 限制过期和无用信息 |
| 单节点辅助连接上限 | 避免信息过载 |
| 单节点辅助通道总贡献上限 | 防止很多小权重连接累计主导表示 |
| 探索展示预算与冷却时间 | 控制反馈获取频率和重复展示 |
| 启用阈值、撤销阈值 | 减少频繁切换 |

可讨论启用阈值高于撤销阈值的滞回规则，降低抖动。下限应保证合法状态与必要服务，不强迫每个节点拥有辅助连接；没有可信候选时允许连接数与贡献为零。

## 8. 与第一阶段的衔接

共用证据记录，不直接共用决策权重。

- 第一阶段判断某个用户—物品对的负采样资格、可信度与训练价值。
- 第二阶段判断某种辅助关系是否用于表示传播，以及贡献大小。
- 探索展示策略决定获取哪些反馈，分别提供给两个模块。

当同一用户—物品关系同时被标记为高可信正向连接和高可信负例，必须处理状态冲突，不能直接进行相反更新。所有模块使用同一已确认事件口径和版本。

建议一个时期内固定推荐模型及连接快照用于反馈收集，再批量更新证据、采样规则与模型。具体快慢更新周期待定；目的在于可解释、可回放地比较策略。

## 9. 首轮对照与验收

| 组别 | 改动 | 回答的问题 |
|---|---|---|
| P0 | 原 LightGCN | 新协议下的参考 |
| P1 | 只扩充边缘推荐候选 | 是否仅曝光增加带来收益 |
| P2 | 固定辅助连接及固定贡献 | 补充邻域是否有用 |
| P3 | 证据门控、可撤销连接 | 证据与更新规则是否有用 |
| P4 | 学习策略管理连接 | 学习是否优于启发式 |
| P5 | 自适应层融合，无辅助连接 | 深度/融合独立贡献 |
| P6 | 辅助连接 + 自适应融合 | 两者是否互补 |

展示类组别使用同等探索预算；结构类组别记录连接、参数与训练成本。最终与第一阶段做无模块、仅第一阶段、仅第二阶段、两者组合的四组比较。逐步筛选方案，不默认全部进行完整长训练。

同时报告总体排序、固定目标群体的分组效果、长尾曝光与覆盖、拒绝/重复展示、连接撤销率、原节点表示变化及运行成本。

边缘群体按预先确定的原图或时期起点快照定义，保留固定群体跟踪；补边后节点不再低度，不能因此从评估群体中消失。

对照 [GALORE](https://scholars.cityu.edu.hk/en/publications/improving-long-tail-item-recommendation-with-graph-augmentation/) 的物品间补边、[LAGCL](https://arxiv.org/abs/2309.11177) 的长尾邻域补充，以及 NTCF 的自适应深度。加入强化学习必须证明收益不能被简单的固定或证据门控规则解释。
