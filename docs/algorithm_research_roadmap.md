# LightGCN 算法研究路线：可靠负采样 → 节点自适应传播 → 多兴趣表示

日期：2026-10-12。状态：研究路线已由用户选择；以下机制、超参数和验收口径为待验证设计，并非已经实现或取得收益。

2026-10-13 实施进展：第一阶段的独立离线实验入口已编写，含 KuaiRand 时间切分、四组采样、验证训练、检查点恢复和最终汇总。见[实现协议](stage1_implementation.md)、[代码阅读指南](code_structure.md)和[云服务器操作指南](cloud_stage1_runbook.md)。在线反馈管理、第二阶段与多兴趣方案仍属后续研究；不将离线实现视为完整在线策略。

## 1. 目标与范围

依次回答三个问题：

1. 监督信号：哪些未交互物品适合作为负样本，何时提高采样难度？
2. 信息传播：不同用户、物品应该保留哪些传播层的信息？
3. 偏好表示：怎样表示用户的多种兴趣，并针对候选物品选择相关兴趣？

算力不作为选题限制；根据实际资源开销选择本地或云 GPU。研究优先考虑假设是否可检验、贡献是否区别于已有方法，以及是否能解释收益来源。

第一阶段的“可靠性”特指减少不可靠负样本带来的训练干扰。它不自动意味着预测概率校准、抗攻击、冷启动或线上可靠性；这些需要各自的实验定义。

当前历史基线继续作为参考。保留固定训练预算，不默认增加 Early Stopping。本文件不修改模型、数据、权重或训练入口。

持续讨论文件：[第一阶段主动反馈与可靠负采样](feedback_driven_negative_sampling_proposal.md)、[第二阶段边缘缓存与辅助传播](feedback_managed_peripheral_propagation_proposal.md)、[两阶段必须明确的关键约束](stage12_critical_constraints.md)。下面的静态实验协议与真实反馈轨道分别记录；所有新增机制仍是提案。

## 2. 共同实验协议

- 历史基线：提交 `64d05b00fd4008c02ab231d7e988895b472d158c`；Gowalla 原 full train/test、seed=2020、1000 Epoch。文档记录的最终 Recall@20=0.182014、NDCG@20=0.155377、Precision@20=0.056186。
- 新算法轨道：从原训练交互内部固定划分 validation，所有对照使用相同拆分。原测试集只用于最终报告。新拆分下必须重新训练随机负采样基线；历史数字只作参考。
- 图只使用当前实验的训练交互。切分保留每用户最低训练交互数，记录物品零度情况、交互重复和集合交集。
- 负样本候选来自训练未交互物品，不以 validation/test 的交互身份过滤或加权。验证与测试真值不进入采样器或图传播。
- 验证排名屏蔽训练正交互；最终测试排名统一屏蔽训练和验证正交互。验证交互用于该排名屏蔽，不作为拟合输入。若后续采用 full-train 重训，应单独定义协议并为所有方法执行。
- 超参数搜索使用 validation，各组记录搜索次数与训练预算。至少使用三个相同种子的配对运行；确定性容差与设备环境写入运行记录。
- 主指标建议预先指定为 NDCG@20；辅助指标包括 Recall@20、Precision@20、用户活跃度分组、物品流行度分组、运行时间和显存。
- 各阶段保留参数量、负样本数量和计算预算对照。无法同时等预算时分别报告固定更新次数与固定时间下的结果。
- 新运行使用独立实验目录；记录配置、提交、数据指纹、seed、模型及优化器状态，保护原始基线产物。

## 3. 阶段一：可靠性与课程负采样

### 本轮讨论扩展：主动获取真实反馈

用户提出为每个用户维护候选缓存与历史权重，通过阈值触发向真实用户展示候选物品，再根据反馈改善负采样。此方向已记录为第一阶段的创新讨论稿：[用户缓存与主动反馈驱动的可靠负采样](feedback_driven_negative_sampling_proposal.md)。

该提案将偏好估计、不确定性和负例可信度分开，讨论探索预算、证据更新及课程机制。下面的静态离线采样对照仍保留；真实反馈闭环需要额外数据和独立评估协议。具体机制尚未定稿，当前只推进讨论与文档。

### 3.1 假设

H1：最高分未交互物品不总是最有益的负样本。适当区分困难程度和负例可靠性，并按训练状态调节难度，可能提高排序表现与跨种子稳定性。

这是待验证假设。未交互不等于不喜欢；仅凭模型分数或图结构，不能确定某个样本是真负例或假负例。

### 3.2 最小机制

维持 LightGCN 传播、均值聚合和单负样本 BPR。先从合法候选池中选择负样本，不改变主损失；候选池大小与刷新周期单独记录。

- 困难程度：正负评分差或候选排名。
- 潜在正例风险线索：训练图中的协同支持，以及不同预测视图对高分的共识。
- 不确定性线索：不同视图或历史快照的评分分歧。分歧大表示证据不稳定，不能直接解释为假负例。
- 课程：初期保留较多随机或中等难度样本，后期逐步增加可靠困难样本。
- 探索：始终保留一定随机比例，避免采样器完全服从当前模型。

先选择一种风险代理，防止一开始堆叠多个指标。第一版可使用停止梯度的评分快照，固定刷新周期，先检验随机与困难采样的差异，再接入可靠性筛选。评分视图可以来自固定传播层或独立快照，不依赖第二阶段的自适应结构。

采样决策不反向传播。若进一步采用可靠性加权 BPR，视为额外实验变量，单独消融，不能与纯采样改动混为同一贡献。

### 3.3 必要对照

| 组别 | 方法 | 回答的问题 |
|---|---|---|
| S0 | 原均匀随机采样 | 新数据协议下的基本对照 |
| S1 | 候选池最高分采样 | 单纯增加困难程度是否有效 |
| S2 | 温度采样或固定随机/困难混合 | 简单软化难度能否解释收益 |
| S3 | 可靠性筛选，无课程 | 风险代理是否有增益 |
| S4 | 课程调度，无可靠性筛选 | 调度本身是否有增益 |
| S5 | 可靠性筛选 + 课程 | 两者是否互补 |

S1–S5尽量共用候选池大小、候选分布、评分表示和刷新预算。机制确定后，加入 DENS 或 DANS 等最接近的已有方法作对照，核查独创性。

### 3.4 诊断与验收

- 所有采样样本满足正负交互合法性；密集用户和无正交互用户有明确处理。
- 记录负样本评分差、重复率、流行度分布、代理风险、采样时间和刷新开销。
- 如需检查假负例风险，另设训练集内部的隐藏已知正交互探针，仅作诊断；其身份不进入采样选择。它只能测量已知正交互的误采倾向，不能证明所有未交互物品的真实偏好。
- 对主指标做相同种子的配对比较，报告均值、标准差和效果差异；样本量不足时不宣称统计显著。
- 检查收益是否仅来自更多候选、更长训练或流行度偏移；同时报告稀疏用户和长尾结果。
- 若可靠性代理没有稳定增益，记录负面结果，保留表现较好的简单采样对照，重新评估代理；不默认进入模块叠加。

## 4. 阶段二：节点自适应传播与聚合

### 本轮讨论扩展：反馈管理的边缘缓存与辅助连接

用户提出为边缘内容维护缓存，通过指针关联推荐图，使用学习策略及上下限管理。方案记录于[第二阶段文档](feedback_managed_peripheral_propagation_proposal.md)，讨论真实图与辅助通道分离、连接生命周期、节点门控和第一阶段证据共享。

新增方向研究“补充哪些信息”，原节点自适应路线研究“如何选择传播层”；两者分别消融。只增加推荐候选属于曝光改动，不自动证明传播改进。指针的具体语义、目标群体、奖励和连接规则尚待确定。

### 4.1 假设

H2：节点需要的传播信息与局部结构及层间表示变化有关。共享的节点条件化选择规则可能优于全局固定平均，并可与更可靠的监督信号互补。

不预设“稀疏用户一定适合浅层”或“热门物品一定适合深层”，应通过分组分析判断。

### 4.2 推进顺序

1. 全局可学习层权重：作为简单结构对照，不作为主要创新声明。
2. 用户与物品分别使用全局权重：检验两类节点的差异。
3. 共享节点条件化门控：输入训练度数、邻域分歧、层间变化等，输出各层融合权重。避免为每个 ID 独立增加大量自由参数。
4. 只有融合机制得到支持后，再考虑逐层停止传播或改变邻居聚合。

第一版节点自适应融合仍计算全部固定层，改变的是信息选择，不会自动减少图传播成本。真正节省计算需要额外的执行机制和测量。

层间变化只是信息收益的代理，大幅变化也可能来自噪声。对照 ApeGNN、NTCF 等相关方法，明确差异。

### 4.3 对照与验收

保留四组核心实验：原采样/原聚合、阶段一/原聚合、原采样/自适应聚合、阶段一/自适应聚合。再与全局权重及用户/物品分离权重比较。

除排序指标外，检查权重分布、不同活跃度节点的偏好、层数敏感性和额外成本。若权重几乎恒定，或全局权重取得同等效果，应收缩“节点个性化”的结论。

## 5. 阶段三：多兴趣表示与候选匹配

### 5.1 假设

H3：单一用户向量可能将不同兴趣混合。多个兴趣表示与候选条件化匹配，可能提高对不同偏好子集的覆盖，并与自适应传播互补。

### 5.2 最小机制与扩展

- 第一版为用户维护固定数量的兴趣表示，让历史交互通过路由或软分配形成不同兴趣。
- 针对候选物品，比较最大兴趣评分与软融合评分。训练、采样和评估必须使用同一个实际评分函数，不能仍用单向量近似却声称完全等价。
- 若阶段一使用旧评分缓存，修改多兴趣结构后重新建立与新评分一致的缓存，检查过期误差和成本。
- 监测兴趣使用比例、表示相似度和分配熵；只有发现塌缩后，再评估多样性约束的必要性。
- 先验证固定兴趣数，再探索自适应兴趣数。超图或兴趣原型作为后续扩展，不能把“多兴趣有效”与“超图有效”合为一个无法区分的结论。

### 5.3 实用能力的验证边界

仅有 ID 交互时，可以验证协同偏好覆盖和列表多样性，不能据此自动赋予兴趣“运动”“音乐”等语义名称。语义解释需要标签、文本或其他辅助信息。

静态交互数据不能证明短期兴趣适应能力；真正的零交互冷启动也需要额外信息。若要验证兴趣随时间变化，应增加有时间戳的数据与时间切分。

与参数量匹配的单向量高维模型比较，排除纯容量收益。检查总体准确率、覆盖率、列表多样性、兴趣塌缩及稀疏用户表现；嵌入距离上的多样性只作为代理，不直接等同于语义多样性。

## 6. 组合与独立贡献

用 A=可靠性/课程采样、B=节点自适应聚合、C=多兴趣表示标记模块。

最终候选方法需要原基线、A、B、C、A+B、A+C、B+C、A+B+C八组消融；使用统一协议，说明适用于不同评分函数的采样适配。阶段二先完成四组，阶段三再补齐。

阶段验收只说明该模块是否值得继续研究，不等于通过发表审查。精确独创性需要针对最终机制补充检索，并与最接近的方法直接比较。
