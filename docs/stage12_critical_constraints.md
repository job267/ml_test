# 第一、第二阶段必须明确的约束与实验检查

日期：2026-10-12。用途：宽泛方案转为实现前的共同讨论清单。具体机制仍待定，但下面的事实区分和验证边界应贯穿实现。  
关联：[第一阶段](feedback_driven_negative_sampling_proposal.md) · [第二阶段](feedback_managed_peripheral_propagation_proposal.md) · [总体路线](algorithm_research_roadmap.md)

## 1. 当前最大的前提：反馈从哪里来

Gowalla 静态交互文件不能完整支持真实展示闭环，没有曝光、位置、未点击和选择概率记录。先决定采用交互原型、合适日志还是二者结合，并明确内容、反馈形式和评价任务。

仅用模型或模拟用户生成反馈，可以调试流程，但不能证明真实用户偏好被纠正。更多显存无法替代这些数据。

## 2. 关键问题、后果和必须落实的检查

| 问题 | 不处理的后果 | 必须明确或检验 |
|---|---|---|
| 未交互、未展示、未点击、明确拒绝混为负例 | 将潜在正例误用为可靠负样本 | 保存事件类型、展示位置、可视状态及反馈窗口；只按预先定义证据更新 |
| 一种权重同时控制推荐、采样与补边 | 对同一关系产生互相冲突的决策 | 分开偏好、不确定性、负例可信度、连接贡献及探索预算 |
| 模型分数既生成关系又证明关系 | 形成自我确认闭环 | 高分只能作候选线索；通过独立反馈及直接对照验证，避免只奖励自身高分 |
| 把辅助连接当真实正交互 | 训练标签及图结构被推测污染 | 真实事件与辅助关系分别记录；模拟、相似度或策略选择不能自动升级为真实事件 |
| 缺少边缘定义 | 只增加曝光却声称改善传播，或选择群体随方法变化 | 分开局部边缘、低度、低曝光、零交互；固定群体跟踪 |
| 新边的传播规则不清 | 改变归一化或关系类型却无法解释 | 明确方向、权重、尺度、零度处理；不同关系独立通道或说明合并后的影响 |
| 正反馈与负采样缓存不同步 | 已知正例仍被当负例 | 统一用户—物品状态版本，失效旧样本与在途训练规则可检查 |
| 延迟/重复反馈直接更新 | 重复强化，或在结果到达前认定负例 | 事件去重、反馈窗口、晚到修正和事件时间口径 |
| 多个学习器同时快速变化 | 状态与奖励不稳定，难以归因 | 分阶段训练或固定时期快照，记录各模型/策略/图/缓存版本 |
| 奖励只设为高损失、连接数或曝光数 | 偏向假负例、无用补边或低质量展示 | 用户价值、证据及训练效果分别测量，曝光/度数增长不作为效果充分证据 |
| 永久缓存、强制最低连接数 | 错误关系固化，或为满足数量引入噪声 | 过期、衰减、撤销与无候选退化；没有合适关系时允许零辅助贡献 |
| 只有每条边权重上限 | 多条小权重边仍主导节点 | 限制节点的辅助总贡献并检查多层累计影响；上限不保证天然安全 |
| 线上采集数据的策略不同 | 更好结果可能只因获取了更多/不同数据 | 匹配展示与训练预算，区分数据增益、选择增益、传播增益 |
| 用未来反馈或验证/测试身份构图和采样 | 数据泄漏 | 截止时间回放；辅助候选只能来自合法信息；训练内探针不进入决策 |
| 选择概率与候选池缺失 | 无法分析曝光偏差或可靠回放 | 记录门控和条件选择过程、概率、位置与候选池；有支持不等于估计必然精确 |
| 仅总体准确率或点击率提高 | 长尾可能受损，或可靠性未改善 | 固定群体指标、明确负反馈、已知正例误采、重复曝光和成本共同报告 |

## 3. 原图与辅助图的数学语义

加入边会改变相关端点度数和归一化权重；即使边权很小，也不能断言对原传播没有影响。门控需要处理两通道的尺度，多层传播需要实测累计影响。

物品—物品关系不是原用户—物品二部图关系。明确拒绝不能直接作为原 LightGCN 的负权邻接项使用。若选择有符号图或多关系图，必须独立定义算法与对照。

用原图统计定义目标群体；辅助边不制造“真实交互量增加”的证据。完全没有交互和内容信息的节点单独处理，不宣称缓存解决零交互冷启动。

## 4. 共享证据与状态一致性

事实记录保存事件来源和时间；偏好、可信度与不确定性是推断，不是事实。两个阶段可以共享事件，但使用不同决策字段。

最低行为检查包括：

1. 重复事件不会重复增加计数或证据。
2. 确认正交互后，相应负采样资格失效；晚到反馈可修正待确认状态。
3. 启用辅助关系不会自动增加真实交互数或正样本标签。
4. 没有合法候选、没有可靠负例、预算不足、缓存过期时均有可运行退化行为。
5. 未确认可视或尚未完成反馈窗口不自动成为高可信负例。
6. 关闭新增模块后，在相同输入、权重、随机状态下恢复原模型的输出和梯度语义。
7. 图、评分缓存、策略和训练批次的版本能够对齐或明确失效。
8. 回放任何时刻不会使用尚未到达的反馈。

这些是后续新增功能的测试方向，本轮未编写实现或测试。

## 5. 学习策略的必要性与奖励边界

手工权重更新与阈值规则可作为启发式基准，不能仅因有缓存和反馈就称为强化学习。即时选择可先研究 Bandit；持久连接的长期影响需要状态转移、奖励归属和学习算法定义。

第一版只让一个新策略学习有限动作，其余使用固定规则。建议先检验简单随机/固定规则，再检验证据门控，最后加入学习策略；不把模型复杂度作为创新的证据。

采样奖励不只追求高 BPR 损失，展示奖励不只追求信息量，结构奖励不只追求补边数量。具体权衡应在独立验证中选择，原测试集不反复参与策略奖励或调参。

## 6. 公平评估与反事实边界

保留历史基线，区分静态算法轨道与在线反馈轨道。至少比较：无新模块、仅第一阶段、仅第二阶段、组合方案，并在模块内部加入随机、固定规则和证据门控对照。

负采样机制对照尽量共用合法反馈快照；在线策略比较使用匹配预算的随机分组或满足条件的日志估计。动态补边改变其他用户的表示，在线分组可能相互干扰，应决定采用隔离模型快照、分离状态或其他有依据的实验单位。

记录真实选择概率及支持范围。若新策略选择历史从未有机会展示的物品，不能从缺失结果中直接推断其奖励；反事实方法还需要支持、正确日志及估计条件。仅保存概率不保证无偏或低方差。

模拟结果、静态排名结果和真实互动结果分别报告。至少做多种子对照；在线反馈样本稀少时报告不确定性，不预设显著提升。

## 7. 设计冻结前先回答的四个问题

1. **数据与反馈**：推荐什么，真实反馈/曝光日志来自哪里，哪些事件具有怎样的证据强度？
2. **图与状态**：辅助关系是什么，“指针”怎样进入传播，何时启用、过期、撤销？
3. **动作与奖励**：学习策略究竟决定哪一个动作，奖励依据什么，预算怎样限制？
4. **实验与归因**：怎样匹配数据与成本，什么结果能够分别支持可靠性和传播改进？

这四项不清晰时，可以继续概念讨论和流程原型，但不应将完整长训练当作验证方案的替代。

## 8. 已核对的相关资料

- [Bandit Learning with Implicit Feedback](https://proceedings.neurips.cc/paper/2018/file/d8c9d05ec6e86d5bbad7a2f88a1701d0-Paper.pdf)：区分查看与相关性，解释未点击反馈的不完整性。
- [Unbiased Offline Evaluation of Contextual-bandit-based News Article Recommendation Algorithms](https://arxiv.org/abs/1003.5956)：特定数据收集与回放条件下的评估研究，不支持任意静态交互日志直接评价新探索动作。
- [Reinforced Negative Sampling for Recommendation with Exposure Data](https://www.ijcai.org/proceedings/2019/309)：曝光与强化负采样的相关先例。
- [NTCF](https://arxiv.org/html/2608.10297v1)：原二部图上的节点自适应传播深度。

其余约束来自当前方案的状态、数据与数学语义分析，是待落实的设计要求，不是已经取得的实验结论。
