# 当前阶段的研究推进策略

日期：2026-10-17（北京时间）。这是根据现有实验提出的推进方案，不表示后续模块已经实现或已经启动。运行中的公开复现继续按原计划完成；所有新 GPU 实验仍使用现有 conda `gcn`，仅物理 GPU 0，串行执行。

## 1. 当前判断与策略

保留 LightGCN 作为骨干，保留两套独立的数据/评价协议。先把实现和评价对齐，再拆分数据因素；之后每次只检验一个有明确机制的新改动，达到预先写明的条件才扩大实验。

- 当前协议下，匹配初始化的 LightGCN 相对 MF/BPR 的三种子验证 NDCG 提升约 15.56%，说明图传播有价值。
- 当前困难采样对总体 NDCG 的约 5.87% 提升，伴随稀疏用户约 18.73% 的下降；额外证据加权没有复现稳定的增量收益。
- 降低定向比例、改变候选来源等已有消融没有同时修复总体和稀疏用户表现。继续机械搜索相同全局权重，优先级较低。
- 当前总体最佳点集中在早期，100 轮没有刷新最佳成绩；长尾和训练零正向度目标仍缺少有效覆盖。
- 两套验证集的相同 Popular 排序 NDCG 相差约十倍，低频目标占比也明显不同。现阶段不能把跨协议分差直接归为实现或算法能力差距。

证据见 `analysis/baseline_calibration_20261016/comparison_interpretation_20261017.md` 和各轮 `results_review.md`。

## 2. 第一优先：完成校准，核对两套实现

先完成正在运行的第五个公开种子，审计五种子结果、早停和检查点。作者原样屏蔽与修正屏蔽的结果分别保留；不根据测试成绩改配置或重选模型。

公开复现使用作者实现，尚不能证明本地训练器已经对齐。下一项核对使用作者固定的训练/验证数据，依次固定：

1. 用户/物品映射、训练边、图归一化及候选屏蔽。
2. 相同的初始权重，直接回放相同的用户—正例—负例批次及批次顺序。相同 seed 不自动等于相同样本序列。
3. 损失、正则与优化器更新。
4. 相同权重下的验证评分和指标；明确数值精度、并列排名与作者四舍五入的差异。

先做同批次输出/梯度与少量更新核对，发现差异先定位；通过后再安排短程训练曲线对照。避免为排查实现问题反复重跑五组长训练。

验收：差异在事先约定的数值容差内或有可复现的明确解释；相同输入与屏蔽的验证评价一致；训练轨迹差异不能来自未说明的采样、选轮规则或未来信息。历史源码、检查点和正式套件的选择规则不改动；新适配与诊断放在独立目录。

## 3. 第二优先：拆分标签和曝光来源

用相同的原始日志和固定日期窗口，在验证集做 2×2 诊断：

| 正反馈定义 | 验证来源：全部已记录曝光 | 验证来源：随机曝光 |
|---|---|---|
| click | 点击／全部 | 点击／随机 |
| engagement | 深度互动／全部 | 深度互动／随机，即当前任务方向 |

这组诊断保持时间窗口不变；不能同时再切换为作者的 8:1:1 划分。主诊断尽量固定词表和共同可评用户，并单列原协议完整人群的结果；标签改变导致的用户筛选、词表和样本量变化要逐项记录。

先用一个种子、约 30 轮检查两种标签的纯 LightGCN；同一训练模型可在合法的不同验证来源上评价，评价来源本身不要求再训练一份相同模型。若共同用户限制改变了训练图，则重新训练，不冒用原检查点。所有准备数据使用独立清单和指纹。

同时报告 Popular、随机期望、目标流行度和分组指标，回答低分在哪个条件出现。不同任务之间不计算算法提升比例。末段仍明显改善时，再预先统一延长相关对照的观察窗口。

验收：能明确区分标签定义、评价来源、评价人群及实现的影响，形成可复查的数据诊断结论；不要求把更难任务改成高分任务。

## 4. 第三优先：给负采样一个有限、可否证的机制实验

下一轮优先候选是按训练证据量限制干预，先采用可解释的固定规则。例如：训练历史少的用户回退到 uniform，其余用户沿用冻结的困难采样对照。阈值只依据训练统计预先确定，不按验证结果反复调节。

最小对照为 uniform、原有证据候选困难采样、仅新增用户保护规则。先不叠加新 beta、去重上限、新损失或新传播模块。相同物品表示和图会被用户共享，所以采样回退并不保证某组用户的指标自动恢复；这是待验证机制。

先用旧种子短程诊断，记录全部尝试；有清晰信号后再做至少三个配对种子。新种子用于检查随机性稳健性，不把它称为独立数据验证。旧对照只能在数据、代码、训练预算和评价规则完全一致时复用。

建议在新实验开始前冻结候选筛选线：

- 三种子平均总体 NDCG@20 高于 uniform。
- 三种子平均稀疏用户 NDCG@20 不低于 uniform，平均 Recall@20 不下降。
- 不依赖单个种子支撑收益；检查每个种子的方向。所有分组和 Recall 均取总体指标选定的同一轮。
- 同时报告负例集中程度、长尾绝对命中数与成本；零到一两个命中不解释为长尾问题已解决。

这些是决定是否进一步复核的筛选条件，不是统计显著性证明。新实验的窗口和选轮规则事先固定；不改变历史套件口径。

停做条件：这个有限实验仍不能兼顾总体和稀疏用户时，保留 uniform 等简单基线，记录该分支当前缺少支持，暂停相同权重的进一步网格搜索。第二阶段可以独立在 uniform 骨干上验证，不以第一阶段必须成功为前提。

## 5. 第四优先：先验证信息来源，再学习辅助连接

长尾方向先回答“新增信息是否有用”。若采用内容或属性，只使用训练截止时已可获得的信息；无法核实时间来源的整段统计特征暂不作为训练输入。

按顺序比较：原 LightGCN、只增加该特征的简单模型、采用固定规则融合辅助信息的模型。只有看到额外融合收益后，再比较可学习门控或连接管理。需要排除收益仅来自增加特征或参数量。

真实交互与辅助关系分开，辅助关系带来源、贡献上限、过期和撤销规则。目标长尾群体由原训练图固定，不能补边后把它们移出评估组。无正边且无辅助信息的节点不能仅靠缓存获得个性化证据。

验收：固定长尾群体的绝对命中与排序指标在多个种子上改善，总体和稀疏用户没有新的明显退化；学习机制优于简单的固定规则，额外代价可说明。只有通过这些对照，才扩大辅助连接实验。

## 6. 后续：真实反馈闭环、策略学习和多兴趣

先明确实际可获得的展示/反馈渠道和可回放条件。静态日志和模拟用户不能提供任意新动作的真实结果。

用户记忆先保存事实及时间，分开记录偏好、不确定性与负例证据。先比较相同探索预算下的随机与简单固定策略；确有需要时再引入轻量学习策略。即时展示选择可以研究 Bandit；持久改变图结构的长期决策需要额外定义状态、动作和奖励，不由“用了缓存”自动成立。

多兴趣表示作为独立后续问题，先证明单一兴趣混合是瓶颈，再做容量匹配的对照。避免同时改变反馈采集、负采样、图结构和用户表示。

## 7. 眼前的执行顺序

运行中的公开复现收尾 → 在作者训练/验证数据上核对本地实现 → 标签/曝光来源诊断 → 一个有限的用户保护采样实验。之后依据证据决定保留哪条分支，再安排独立的长尾信息补充。

所有新实验以验证集诊断为主；候选与选择规则冻结后，按预先记录的方案做最终测试。本项目原任务的测试集保持隔离，已看过的公开测试成绩不作为反复选配置的依据。此文件没有启动新训练或修改当前队列。
