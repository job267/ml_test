# 同数据实现核对与标签/曝光来源诊断

按用户确认的[推进策略](../../docs/research_execution_strategy_20261017.md)执行前三项：现有公开复现收尾、同数据实现核对、标签/曝光诊断。所有脚本位于新目录，原 `code/*.py`、`scripts/*.py`、作者文件与历史实验保留原字节。未添加新的主动反馈、困难采样、辅助传播或多兴趣模块。

## 执行顺序与设备

1. CPU 完成数值预检、回归测试和训练/验证数据准备。
2. 后台序列等待 `runs/baseline_calibration_20261016/completion.json`、完成状态及原队列锁释放；审计五个公开种子的选轮、结果及检查点。
3. 使用 **conda gcn、物理 GPU 0** 做完整实现核对。GPU UUID 必须与 `nvidia-smi -i 0` 一致。核对不通过时，不启动标签实验。
4. 顺序训练 engagement、click 两个纯 LightGCN 模型，各先 30 轮，每轮同时评价两类曝光目标与两类验证人群。
5. 若任一共同用户验证视图的 NDCG 最佳点出现在 26–30 轮，则两个模型统一从断点延长至 60 轮；否则在共同 30 轮结束。决策只用第一窗口的验证记录并保存，不看 test。

CPU 数据准备可以与原 GPU 作业并行；本项目自己的两组 GPU 作业不会重叠。没有结束其他用户进程，也没有新增定时通知服务。

配置：`configs/protocol_alignment_20261017.json`。运行中的配置、原源码及本目录 Python 驱动都会冻结指纹；请勿在后台序列运行时修改它们。

## 实现核对的范围

作者固定版本为 `7753efd0a8cf3aaed9b150a3d835dbaa8fe0e50d`。训练/验证字典和图缓存逐一校验 SHA256；本步骤不加载作者或本项目 test 标签。通过 AST 提取固定文件中**未经修改的方法体**，排除作者全局 CLI 和 IO 初始化。仅编译 vanilla LightGCN、原 BPR 采样方法、原验证评价器及指标函数。

- 独立重建本项目归一化图，与作者缓存比较；单独记录浮点误差。
- 在同一图和初始化权重上检查表示、原始评分、原生目标、梯度。
- 两套实现回放相同训练三元组及批次顺序，比较 Adam 更新。相同 seed 不自动等于相同采样序列，因此不把两个 RNG 的不同输出误报为模型错误。
- 用相同固定表示执行两套真实验证评价器。作者指标四舍五入到四位小数；项目研究入口使用原始 dot-product，不使用 legacy `getUsersRating` 的 sigmoid 值。
- 完整 GPU 核对包含 64 步更新预检和 3 轮相同样本回放。两套原生损失公式保留；容差在配置中预先给定，未要求位级一致。

已确认的数学差别：作者使用 `-log(sigmoid(margin)+1e-10)`，本项目使用稳定的 `softplus(-margin)`。在普通范围很接近，在极端负间隔处作者公式会饱和；例如 margin=-30 时，作者 loss 约 23.025、梯度约 -0.000935，项目 loss 约 30、梯度约 -1。因此不能宣称对任意输入完全同式，也不能仅凭这个人造极端例子断言它导致了当前分数差距。

CPU 实际数据预检使用相同全训练图、257 个固定随机抽取的验证用户、4 次更新。初始表示/评分一致；梯度最大差约 5.46e-12，四步后参数最大差约 5.96e-8，真实评价器在作者四位小数口径下一致。完整 GPU 核对仍须独立完成。

## 数据诊断怎样控制变量

原始日志固定为当前 prepared manifest 记录的三份 KuaiRand-Pure 文件，逐一核验摘要。只处理 `date<=20220503` 的反馈；更晚的行在解析反馈标志前跳过，既不生成也不读取当前任务 test 目标。

同一次前缀读取同时生成 click、engagement 两种标签。去重直接复用原 `event_signature`；冲突正反馈与 hate 按原规则排除。原有 engagement 训练词表、训练正对、随机曝光验证正对必须逐项重建一致，否则准备失败。不会覆盖原数据目录。

- 两种模型使用两种标签都满足最低训练正例数的**共同训练用户**。这一步只依赖训练数据。
- 物品词表固定为全部训练曝光物品。
- 主评价用户为四种验证视图都存在目标的用户交集；这只影响报告，不反向改变训练图或训练用户资格。
- 每轮采样数固定为两种共同用户训练正对数量的较小值，保持优化器更新预算相同。
- 一个模型的同一份全物品排名同时评价 random/all；每个视图都屏蔽该标签的训练正例。
- 主结果比较同一轮数（1/5/10/20/30，延长时还包括60），不为每种目标分别挑最高分。辅助结果按每个标签的共同用户 random NDCG 选一轮，其余视图也取该轮。

额外报告各视图的完整可评用户结果，以及 native 原生人群的数据统计、Popular 和精确随机期望；神经模型的因子对照仅训练在共同训练人群。不能把共同人群模型称为原生全体人群重训。原稀疏/长尾分组定义来自各自标签训练图，跨标签的这些分组并非固定身份，主对齐只针对相同 overall 用户群体。

这是单种子的协议诊断，分数变化表示任务条件的变化，不表示新算法提升，也不是完整独立确认。没有把未知或未来正例身份用来过滤训练负例。

## 输出、启动和恢复

输出根目录：`runs/protocol_alignment_20261017/`。

- `data/manifest.json`：原始文件、数据摘要、两种人群/标签统计、原协议重建检查与指纹。
- `cpu_preflight_final/completion.json`：CPU 数值预检。
- `sequence_plan.json`、`status.json`：冻结计划、当前阶段和进程。
- `prerequisite_audit.json`：原公开五种子完成核验。
- `gpu_alignment/`：完整 GPU 对齐结果、采样回放、最终两套权重。
- `factorial/{label}/`：检查点、逐轮四视图结果、验证排名和状态。
- `summary.md`、`comparison.json`：持续汇总和同轮数比较。

```bash
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=0 OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 MKL_NUM_THREADS=4 \
conda run --no-capture-output -n gcn python -u analysis/protocol_alignment_20261017/run_sequence.py
```

恢复相同序列追加 `--resume`，只允许相同数据、源码和配置。完整对齐失败会停止后续阶段；原始失败材料保留，先定位原因，不为使结果通过而事后放宽容差。后台状态每 30 秒更新，最终生成完成标记；不承诺自动向聊天发送通知。
